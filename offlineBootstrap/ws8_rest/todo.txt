A feladatok megoldása során okostelefonokkal fogunk dolgozni és kliens-szerver architektúrát építünk.
Két projekre van szükségünk:
- szerver oldali projekt -> adatbázis + API végpontok, C#, ASP.Net Core
- kliens oldali projekt -> webes megjelenítés, HTML, JS, CSS

Tanulmányozza a kapott kiinduló állományokat.
A server nevű mappában találja a szerver oldali projektet. Ezt Visual Studio-ban nyissa meg.
A client mappában pedig a kliens oldali projektet. Ezt Visual Studio Code-ban nyissa meg.

A kliens felépítése a szokásos: index.html, app.js, style.css, offline bootstrap.
A szerver projektben egy ASP.Net Core projetet talál. Ebben az adatbázis réteg teszt adatokkal már implementálva van.
Az EntityFramework Core nugetek már hozzá vannak adva a projekthez.

***API VÉGPONTOK ELŐKÉSZÍTÉSE***
A SmartphoneApiController fogja biztosítani a végponton keresztüli hozzáférést az adatbázisban tárolt adatokhoz.
Az adatbázis a _repository fielden keresztül érhető el, az ISmartphoneRepository által kiajánlott metódusokkal.

Hozza létre a SmartphoneApiController típusban az alábbi metódusokat.

public IEnumerable<Smartphone> GetSmartphones()
{
    return _repository.ReadAll();
}

public Smartphone? GetSmartphone(int id)
{
    return _repository.Read(id);
}

Ahhoz, hogy ezek valóban végpontokként legyenek használhatók el kell látnunk őket a megfelelő attribútumokkal.
[HttpGet] és [HttpGet("{id}")]
Ezek a Microsoft.AspNetCore.Mvc namespace-ben találhatók.


***API CONTROLLER ELŐKÉSZÍTÉSE***
Ahhoz, hogy az imént elkészített végpontokat valóban használni tudjuk, elő kell készítenünk az azokat publikáló controllert.
Származatassa le a SmartphoneApiController típust a ControllerBase-ből.
Adja hozzá az alábbi attribútumokat.
[ApiController] és [Route("[controller]")]
Utóbbi teszi lehetővé, hogy majd 'smartphoneapi' néven érjük el a böngészőből.

Adja hozzá az alábbi hívásokat a szerver projekt Main metódusához.
Ügyeljen rá, hogy a megfelelő helyen hívja meg azokat!
-> a builderen hívott funkciókat még a builder.Build(); hívás előtt
-> az appon hívott funkciókat még az app.Run(); hívás előtt

builder.Services.AddControllersWithViews();

app.UseRouting();
app.MapControllerRoute(
    name: "default",
    pattern: "{controller}/{action=Index}/{id?}"
);

***ÚJ ELEM LÉTREHZÁSA***
Új elem létrehozásához egy új végpontra van szükségünk.
Vegye fel az új végpontot a SmartphoneApiController-ben.

[HttpPost]
public void CreateSmarthpone([FromBody] Smartphone smartphone)
{
    _repository.Create(smartphone);
}

Figyelje meg, hogy a metódusra most a [HttpPost] attribútum került.
A paraméterre pedig a [FromBody], ezzel tudjuk megmondani, hogy nem a hívás paramétere tartalmazza
majd az adatot, hanem a request body része.

Swaggerrel ellenőrizze le, hogy használható-e az új végpont.
Töltse újra a klienst a böngészőben, és ellenőrizze, hogy az új elem bekerült-e a listába.

await fetch('http://localhost:5047/smartphoneapi', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(smartphone)
})

***ELEM TÖRLÉSE***
Egészítse ki a deleteSmartphone(id) függvényt az app.js-ben.
Figyelje meg, hogy itt a request típusa 'DELETE', a törlendő elem ID-ját pedig paraméterként kell átadnunk a hívás során.
A confirm hívással egy promptot fog küldeni a felhasználónak.

await fetch(`http://localhost:5047/smartphoneapi/${id}`, {
            method: 'DELETE'
        });

Egészítse ki a displaySmartphones() függvényt.
Vegyen fel egy új <td> elemet az 'Actions' oszloppa.
Ebben adjon hozzá egy gombot, a gombra állítson be az előbbi deleteSmartphone(id) függvényt event listener-ként az onlick-re.
Figyeljen rá, hogy annak az elemnek az ID-ját adja át paraméterként, amelynek a sorában lévő gombra kattint.

Implementálja az API végpontot a szerver alkalmazásban.

[HttpDelete("{id}")]
public void DeleteSmarthpone(int id)
{
    _repository.Delete(id);
}
